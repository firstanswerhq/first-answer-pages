F1 matches the design as written. A fuzz of 60,000 random inputs gave 0 throws, and every accepted link was https, had no user name or port, was 1,000 characters or fewer, and was on a listed host. Look-alike hosts, `http`, `javascript:` and `data:` are all refused. The README additions (V70) read right.

The design itself lets a few redirect addresses through. Add V71 to V73 to tasks.md under "Review fixes" in a new section "X. F1 review (`review-2026-11-22-f1.md`)", then fix them. Add tests only: don't change any existing test. No shell commands.

## V71. Redirect-style addresses pass as review links (must fix)
The listing page will show these as "See our reviews on Yelp / Google / Facebook", so the label would vouch for a link that can lead anywhere. Accepted today:
- `https://www.yelp.com/biz_redir?url=https%3A%2F%2Fevil.tld`, because the path only has to start with `/biz`. `/bizarre` passes too.
- `https://maps.google.com/url?q=https://evil.tld`, because any path is allowed on that host.
- `https://www.facebook.com/l.php?u=…`.

Fix in `reviewsLinkHost`:
- Yelp: accept only paths starting `/biz/`.
- `google.com` and `maps.google.com`: refuse the path `/url`.
- `google.com`: accept `/maps` only as exactly `/maps` or starting `/maps/`.
- Facebook: refuse `/l.php` and paths starting `/flx/`.

Add each as a refused case in the tests, and update the design's host list to match.

## V72. The link must start with `https://` (must fix)
`https:google.com/maps` and `https:\\google.com\maps` are accepted and stored as typed. In a page's `href`, `https:google.com/maps` is read by browsers as an address on our own site, so the link would be broken. Require the trimmed text to start with `https://` (any letter case). Test both forms as refused.

## V73. "On the page" Facebook links
`reviewsLinkOnPage` accepts `facebook.com/reviewsfake`, because the path only has to contain `/reviews`. Accept only a path that ends with `/reviews` or contains `/reviews/`. Test it.
