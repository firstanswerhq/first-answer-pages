## V89 `/verified` is a 404 when verification is off, so the sitemap must not list it then
Failing test: `test/sitemap-main-pages.test.js`, "F11: each listed page returns 200 and is not marked noindex": `/verified` gave 404.
Why: `createVerifyRouter` in `server/routes/verify.js` returns an empty router when `ctx.trust` is missing (no provider keys), so every address it owns, `/verified` included, is a 404. The design line for Feature D assumed `/verified` is always served. Kiro flagged this risk in its F11 summary; it was a good call.

Requirement 22 says the sitemap lists only pages that return 200 and are not noindex. So:
- List `/verified` only when verification is on (the same condition the verify router uses: `ctx.trust` is present). `/about`, `/privacy` and `/rise` stay.
- `mainPages` needs to know that. Pass it what it needs from `ctx` (for example a second argument or a flag), and keep it a pure function that tests can call.
- Fix the design line under "Feature D, Sitemap" and the F11 task line to say `/verified` is listed only when verification is on.
- Tests (new file only): with verification off the sitemap has `/about`, `/privacy`, `/rise` and no `/verified`; with verification on (fake trust providers, as the existing verify tests build them) it has `/verified` too; in both cases every listed page returns 200 with no noindex. Change the F11 assertions in `test/sitemap-main-pages.test.js` that expect four pages always (that file is new in F11, so changing it is fine). Do not change any older test.
