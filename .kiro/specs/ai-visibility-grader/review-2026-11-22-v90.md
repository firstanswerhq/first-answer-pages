## V98 (Medium) `normalizeWebsite` keeps punctuation in the host
Typing `"=A.9KMCY` in the owner's Website box is stored as `https://"=a.9kmcy/`. The gap is in `normalizeWebsite` itself (`server/lib/listing-fields.js`) and was there before V90; the short form only makes it easier to reach. Called directly, `https://"x.com/`, `https://a'b.com/`, `` https://a`b.com/ ``, `https://a{b}.com/`, `https://a&b.com/` and `https://a;b.com/` all come back unchanged.
Every output escapes the value today, so nothing can be exploited, but a stored value should be clean on its own.
Fix: in `normalizeWebsite`, after the trailing dot is removed, refuse any host that does not match `^[a-z0-9.-]+$`. International names arrive as `xn--...`, so they still pass.
Tests (new): `https://"x.com/`, `https://a'b.com/`, `` https://a`b.com/ ``, `https://a{b}.com/`, `https://a&b.com/`, `https://a;b.com/` and the short form `"=a.b` are all left out; `https://xn--caf-dma.fr/` and `https://my-shop.example.com/` are kept.
Check whether `reviewsLinkHost` needs the same rule; it only accepts a fixed list of hosts, so it should already be safe. Say what you found.

## V99 (Low) The canonical link trusts a base address with odd characters
`riseCanonical` (and the same check for the `/grade` canonical) accepts a base address such as `http://x.test"><b>`. Only the operator sets that value, and the page escapes it, but keep the rule tight: build a canonical link only when the base address is `http://` or `https://`, then a host of letters, digits, dots and hyphens, then an optional `:port`, and nothing else (an optional single trailing `/` is fine). Use one shared helper for both pages. Tests: the odd base gives no canonical on `/rise`, `/grade` and `/grade/about`; a normal base and a base with a port still do.
